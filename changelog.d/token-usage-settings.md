### Added

- **Provider quota cards for Claude, Codex, and Antigravity (agy).** Settings → Token usage now displays usage windows with percent used and reset time, change since the last check, average tokens per message (Claude and Codex), plan label, and credits. Readings refresh only when you open the tab or click refresh, never on a background polling timer. Claude uses wmux's existing usage API, Codex queries app-server rate limits, and agy reads from a lightweight status-line sensor.
- **Antigravity quota sensor.** A lightweight `quota-sink.js` probe and automated installer merge the `statusLine` setting for agy without replacing existing status lines (chaining them via base64url encoding without Windows quoting issues). It ignores agy's empty placeholder status lines, captures only quota/plan/model/context metrics (excluding private data like email, cwd, or transcript paths), and writes only when values change.
- **Custom surface toggle panel.** Allows inspecting and toggling MCP servers (with individual tools), skills, plugins, hooks, and built-in tools across installed CLIs (Claude, Codex, agy) directly from their configuration files. Features cost badges for hooks, search filtering, an "only changed" view, read-only explanations for fixed items, change preview before saving, and automatic backups before applying changes on the next CLI session.
- **Safe configuration writer and atomic updates.** CLI configuration changes write via atomic files with automatic timestamped backups (`*.bak-wmux-<timestamp>`), strict JSON manipulation, comment- and ordering-preserving TOML editing (preserving `trusted_hash`), pre-commit re-parse verification, and rollback upon failure alongside a versioned `surfaces.json` state store.
- **Per-CLI configuration writers.** Tailored writer implementations for Codex (`config.toml` covering MCP servers/tools, plugins, skills by `SKILL.md` path, hooks by state key, and built-ins), Claude (`settings.json` for MCP servers, tools, skills, plugins by id, hooks, and built-in tools; reading `claude.json` read-only for wmux-managed status), and Antigravity (`settings.json` supporting lowercase booleans, single quotes, MCP servers, skills, plugins, hooks, and built-in tools).
- **Drift detection and reconciliation.** On opening the custom surface panel or switching providers, wmux computes hashes of the on-disk configuration files. If changes occurred outside wmux since the last apply, a drift notice appears with diff previews, allowing you to re-apply your selections or accept external edits.
- **Surface profiles.** Allows snapshotting and restoring toggleable surface configurations across CLI sessions, complete with edit previews, change summaries, and warnings if previously configured items are missing or newly discovered.
- **CLI detection and compatibility checks.** Detects installed Claude, Codex, and Antigravity CLIs, verifies minimum version compatibility, and provides informative status indicators or read-only modes when CLIs are missing or outdated.
- **MCP status section.** Displays the registration status of wmux's MCP server across all installed agent CLIs, offering one-click Register and Re-register actions with status feedback.

### Changed

- **Streamlined Token usage settings tab.** Removed the redundant "Per role" configuration block from Settings → Token usage, as role bindings, models, effort levels, and launch argv previews are already managed in Settings → Roles & fan-out. The token profile picker, change preview, and orchestrator model settings remain in place.
- **Full internationalization for token usage and surface management.** All user-visible strings across Token usage settings, quota cards, custom surface controls, profiles, and MCP status indicators are integrated into the locale system for English, Korean (ko), Chinese (zh), and Polish (pl) with full automated test coverage.
- **Operational notes and CLI behavior considerations.** wmux does not modify running agent panes—all configuration changes take effect starting with the next CLI session. Codex configuration edits are not hot-reloaded by the Codex app server; Antigravity (agy) may overwrite configuration changes if running when settings are saved; wmux core tools do not include `browser_*` or `company_*` tools; the average tokens calculation may return no result when the filesystem is unresponsive; and agy does not provide per-message token telemetry.

### Fixed

- **Surface profiles state race conditions.** Resolved an issue where saving or previewing duplicate profile names or rapid successive requests could leave the surface profiles dialog in a stale state.
- **Antigravity boolean handling and Windows quoting.** Corrected parsing and formatting of boolean values and single quotes in agy settings, and eliminated Windows command quotation errors in the status-line sensor installer.
